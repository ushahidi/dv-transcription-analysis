# Google Cloud Speech-to-Text (Chirp) ASR benchmark

Baseline word-error-rate (WER) evaluation of Google Cloud Speech-to-Text's
Chirp models on this project's African-language test sets - a third engine to
compare against [whisper/](../whisper/README.md) and
[gemini/](../gemini/README.md), scored on the same shared FLEURS clips in
[../data/](../data/README.md).

## Status: not runnable yet

This folder is fully written and structurally ready, but **cannot be run
end-to-end until a GCP project with billing is set up** - that's a manual,
account-level step nobody else can do. Once it exists:

1. Enable the Cloud Speech-to-Text API on the project.
2. Create a service account with Speech-to-Text access and download its JSON
   key (or use `gcloud auth application-default login` instead).
3. Set two environment variables before running anything below:
   ```powershell
   $env:GOOGLE_CLOUD_PROJECT = "your-project-id"
   $env:GOOGLE_APPLICATION_CREDENTIALS = "C:\path\to\service-account.json"
   ```

## Why Chirp, and why it's separate from whisper/ and gemini/

USH-2516 asked whether Chirp 3 could be added the way Whisper is (an
open-weights model this repo loads and runs locally). It can't:

- **Chirp 3 is not open source.** It's a proprietary Google model, reachable
  only through the paid Cloud Speech-to-Text API v2 - no downloadable weights,
  no self-hosting (confirmed via Google's own docs,
  `docs.cloud.google.com/speech-to-text/docs/models/chirp-3`).
- **Swahili support is Preview-status**, and **no per-language WER for Swahili
  is published** by Google or by third-party trackers (Artificial Analysis'
  4.3% WER figure for Chirp 3 is an aggregate over English-centric datasets -
  AgentTalk, VoxPopuli, Earnings22 - not Swahili). The only way to get a real
  number is to run this folder's `run_baseline.py` once GCP access exists.
- **Cost is not the blocker.** Chirp is billed at $0.016/minute (same rate for
  Chirp 2 and Chirp 3, confirmed from Google's pricing page and Artificial
  Analysis). This repo's 20-clip Kiswahili test set averages 14.3s/clip, so
  100 similar clips ≈ 23.8 minutes ≈ **~$0.38** - trivial, and covered many
  times over by GCP's standard $300 new-account credit.

This folder is structurally independent of `whisper/` and `gemini/` - its own
config/metrics/model-calling code, not importing either. The one thing that
*is* shared on purpose is the eval data itself - see
[../data/README.md](../data/README.md); this folder just reads it, it doesn't
download its own copy.

## Layout

```
chirp/
├── lib/            # shared code - config loading, metrics, the Cloud STT client
├── scripts/
│   └── run_baseline.py      # WER report for a Chirp model (see below re: confidence)
├── english/
│   ├── config.yaml
│   └── results/     # generated by run_baseline.py (gitignored)
└── kiswahili/        # same structure
```

## Setup

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r chirp/requirements.txt
```

No torch/transformers here - this folder never loads a local model.

## Running the pipeline (once GCP access exists)

```powershell
# 1. Pull the eval set, if not already done - see ../data/README.md
python data/scripts/prepare_dataset.py --language kiswahili --split eval

# 2. Baseline accuracy (WER)
python chirp/scripts/run_baseline.py --language kiswahili --split eval
```

Confidence is not reported for this engine: Cloud STT v2's Chirp models don't
reliably populate `SpeechRecognitionAlternative.confidence` for a plain
`recognize()` call (it comes back as a constant `0.0`) - rather than surface
that as if it were a real signal, `chirp/lib/stt_client.py` leaves it `None`
and `mean_confidence` in the results comes out `null` accordingly.

Results land in `chirp/<language>/results/baseline_<model>_<split>.{json,csv}` -
same shape as `whisper/`'s and `gemini/`'s results files, so all three are
directly diffable.

## Choosing a model and region

`chirp/kiswahili/config.yaml` defaults to `stt.model: chirp_3` and
`stt.language_codes: [sw-KE]`; `chirp/lib/default_config.yaml` defaults
`gcp.location` to `us-central1`. **Confirm both before a real run** - Chirp
model availability is region-specific, and Chirp 3's Preview-status language
list is narrower than Chirp 2's, so `sw-KE` may not be served out of every
region. Check
[cloud.google.com/speech-to-text/docs/speech-to-text-supported-languages](https://cloud.google.com/speech-to-text/docs/speech-to-text-supported-languages)
once a GCP project exists, and fall back to `stt.model: chirp_2` in
`config.yaml` if Chirp 3 doesn't cover your target region/language - that's a
one-line config change, no code change (this is also the path the ticket notes
for Chichewa/Nyanja, which Chirp 3 dropped but Chirp 2 still covers).

## Adding a new language

Create `chirp/<language>/config.yaml` with `language_name`, `language_code`,
and `stt.language_codes`, plus a matching `data/<language>/config.yaml` (see
[../data/README.md](../data/README.md)) if that language isn't already
downloaded - then rerun the two commands above with `--language <language>`.
